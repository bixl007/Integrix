# @integrix/database

- `schema.prisma` defines User (unique email, optional password for OAuth-only accounts, `emailVerified`, and an optional `avatar` data URL from migration `user_avatar`), Session and OtpCode (both store hashes only and cascade on user delete), Zap (optional `name`; `null` means the UI shows the step chain; `enabled` turns it on or off), Trigger, Action, AvailableTrigger, AvailableAction, ZapRun, ZapRunStep and ZapRunOutbox. Deleting a Zap cascades to its Trigger, Actions and ZapRuns, and from runs to ZapRunStep and ZapRunOutbox. `prisma.config.ts` sets the schema path, migrations path and seed command.
- Run tracking (migration `run_history`): `ZapRun.status` is a string (`queued` by default, then `running`, `success`, `failed` or `halted`, written by the worker; `unknown` for runs older than the migration) with `createdAt` and `finishedAt`. `ZapRunStep` has one row per run and stage (unique together) holding the connector id as text, a status, `error`, `output` and timings. `ZapRunOutbox` rows carry the `stage` to publish and an `availableAt` time; both default to "stage 0, now", so hooks is unchanged.
- `ZapRun.actions` (nullable JSON, migration `zap_enabled_run_snapshot`) holds a `RunAction[]`: the zap's steps when the run started. `src/run-actions.ts` exports the `RunAction` type, `snapshotActions` (write side, used by every intake that creates a run) and `readRunActions` (read side, which returns `undefined` for anything that isn't a snapshot). `run-actions.test.ts` covers both.
- Scheduling (migration `delay_schedule`): `Trigger.metadata` holds a trigger's flat string settings and `Zap.nextRunAt` (indexed) is when a scheduled zap fires next. `src/schedule.ts` holds the `scheduleIntervals` registry (`hourly`, `daily`) with `firstRunAt` (used by the API) and `nextRunAfter` (used by the processor), covered by `schedule.test.ts`.
- `src/index.ts` re-exports `PrismaClient`, the model types and the JSON types (`JsonObject`, `JsonValue`). Services import from `@integrix/database`, never `@prisma/client` directly.
- Schema changes: edit `schema.prisma`, run `bunx prisma migrate dev --name <change>` from this folder with `DATABASE_URL` set, and commit the new folder in `migrations/`. Don't edit applied migrations.
- Connections (migration `connections`): `Connection` holds a user's credential for one connector (`connectorId`, a `name`, and `secret`, the values as JSON sealed by `src/secret-box.ts`) and cascades on user delete. `AvailableAction.connectionFields` lists the credential keys per connector (`email`: `user`, `appPassword`; `solana`: `privateKey`). `secret-box.ts` exports `connectionKey` (SHA-256 of `CONNECTION_SECRET`, or undefined), `seal` and `unseal` (AES-256-GCM with a random nonce and an auth tag), covered by `secret-box.test.ts`. Changing `CONNECTION_SECRET` makes saved connections unreadable.
- `src/catalog.ts` is the built-in catalog as plain data (`builtInTriggers`, `builtInActions` with optional `secretFields`). `AvailableAction.secretFields` (migration `action_secret_fields`) and `AvailableTrigger.secretFields` (migration `trigger_secret_fields`) list the metadata keys the API must mask.
- `seed.ts` upserts the built-in triggers and actions from the catalog idempotently and brings `secretFields` up to date on existing rows. It runs on `bun run dev` and in the Compose `migrate` job. The IDs (`webhook`, `schedule`, `email`, `filter`, `delay`, `solana`) are contracts used by the worker and web registries.
- Scripts read the root `.env` through `bun --env-file`. Verify with `bun run db:generate` and `bun run typecheck`.

## Mailer

`packages/mailer` exports `sendMail({ to, subject, text, html? }, account?)` and `isMailerConfigured()`. With `account` (`{ user, appPassword }`) the message is sent from that Gmail account over a short-lived connection built by `gmailTransport` (spaces in the app password are dropped; `account.test.ts`); without it, from the server account described below. `sendMail` collapses the subject to one line (`formatSubject`) and, unless `html` is passed, sends an HTML version built by `textToHtml` (`src/format.ts`): blank lines become paragraphs, newlines become `<br>`, and everything is escaped. `format.test.ts` covers it. It reads `SMTP_*` and `FROM_EMAIL`, uses STARTTLS on 587 and TLS on 465, gives up on a connection, greeting or idle socket after 10 seconds (so a stuck SMTP server can't hold up the worker's queue), and logs mail to the console instead of sending when SMTP is unset outside production. The API (OTP codes) and the worker (Email action and run-failure emails) both use it, so don't create another transport.
