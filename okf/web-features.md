# Feature components, hooks and lib

- `lib/api.ts` is the only place that calls the backend: `api<T>(path, { method, body, signal })` sends JSON with `credentials: 'include'` (the session cookie), throws `ApiError` with the server `message`, and emits an unauthorized event on 401.
- `lib/session.ts` is the single session store. `useSession()` returns `loading`, `authenticated` (with `user`) or `unauthenticated` from one `/auth/session` request, shared by every component. `refreshSession()` runs after login and `signOut()` on logout. Render nothing while `loading`.
- `lib/links.ts` holds shared URLs. `links.docs` (`/docs`) and `links.apiReference` (`/docs#api`) are in-app, the rest point to GitHub.
- `lib/config.ts` reads `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_HOOKS_URL` (inlined at build) and builds webhook URLs. `lib/types.ts` mirrors API response shapes.
- `hooks/use-api.ts` is an abortable GET hook that returns `{ data, error, loading, reload }`. `reload()` refetches while keeping the current data on screen; call it after a mutation.
- `components/app/`: `AppShell` (desktop sidebar, mobile drawer), `AppSidebar` (Create button, nav with `match` rules, resource links) and `UserMenu` (avatar, theme, home and log-out). Add app routes to the `nav` array.
- `components/marketing/`: `SiteHeader` (section anchors, auth-aware buttons) and `SiteFooter` (link columns, legal bar, wordmark). Shared external URLs live in `lib/links.ts`.
- `components/settings/connections.tsx`: `ConnectionsCard` lists the user's connections, adds one (a connector select, a name and that connector's fields) and removes one, all through `/connection`.
- `components/settings/`: `SettingsCard` (one form per card, with a footer hint and save action) and `profile-forms.tsx` (`NameForm`, `EmailForm` with the code step, `PasswordForm`). Forms call `refreshSession()` after changes so the sidebar updates. The page is `app/(app)/settings`.
- `components/auth-form.tsx` handles login and signup in two steps: credentials (plus a Google button when configured), then the emailed OTP with resend cooldown. Its field names (`username`, `password`, `name`, `code`) match the API's zod schemas.
- `components/zap/`: `zap-card` (dashboard), `step-node` and `step-picker` (builder), and `integration-icon`. `zap-title.ts` holds `zapTitle` (custom name, else the step chain) and `stepsTitle`. `sample-payload.ts` builds an example webhook body from a zap's `{placeholders}` (same syntax as the worker parser) and `webhookCurl()` formats the curl for the zap page and `/docs`. `step-details-dialog.tsx` shows an action's full settings when a step on the zap page is clicked, labelled from `action-fields.ts`. `run-history.tsx` lists a zap's latest runs from `GET /zap/:id/runs` in native `<details>` rows (status, start, duration, then each step's result, error and output) with a manual Refresh and no polling; steps are numbered like the flow, so stage 0 is step 2. `run-format.ts` holds the status registry (`statusInfo`: label and badge variant keyed by the stored status, with a neutral fallback) and `formatDuration`, covered by `run-format.test.ts`. `zap-builder.tsx` is the builder used by the create and edit pages. It blocks saving while a step lacks a required setting (`missingSettings`), which is how a template's empty credential gets filled in. with a `zap` prop it starts from that zap's steps and saves with `PUT`. `field-paths.ts` (`field-paths.test.ts`) turns the zap's latest request (`GET /zap/:id/sample`) into `{placeholder}` suggestions: `fieldPaths` lists dotted paths (an array is offered whole and by its first item, at most four levels) and `fieldSuggestions` adds outputs of steps before the one being edited. In edit mode the builder passes them to `StepPicker`, which shows them as buttons that insert into the last focused field. `trigger-panels.tsx` holds two registries keyed by trigger id: `triggerPanels` (the trigger's card on the zap page: webhook URL and curl, or the schedule and its next run) and `triggerSummaries` (the one-line summary on dashboard cards). `run-history.tsx` shows a Replay button on failed runs. `zap-toggle.tsx` is the on/off switch (`PATCH { enabled }`), and dashboard cards show an Off badge. `zap-actions.tsx` is the Rename, Edit steps and Delete menu with its dialogs, used on the dashboard cards (`onChange` reloads the list) and the zap page (rename reloads, delete returns to the dashboard). It also holds three registries keyed by connector id:
  - `action-fields.ts`: the form fields per connector id, for actions and for triggers that have settings (`schedule`). `connection: true` renders a select of the user's connections for that connector (first option: the server default) and stores the chosen id; `stepSummary` builds the one-line summary on step cards without credentials or connection ids. `secret: true` renders a password input; the API returns a mask for it, and saving the mask keeps the stored value. `action-fields.test.ts` checks the secret flags against the database catalog. A field can carry `options` (rendered as a `Select`) and `optional`.
  - `integration-catalog.ts`: name, kind and description, used by the Integrations page and `/docs`.
  - `connection-fields.ts`: `connectionTypes`, what a user enters to connect their own account per connector id (Gmail account, Solana wallet). Its keys must equal the catalog's `connectionFields` (`action-fields.test.ts`).
  - `webhook-senders.ts`: the services that can call a zap URL (`generic`, GitHub, Stripe, Shopify, Typeform, Calendly, Cal.com, Helius), each with the header hooks checks, setup notes and an example payload. It feeds the webhook trigger's Sender select, the `/docs` sender table and, before a zap's first request, the builder's field suggestions. Ids match the hooks `verifiers` registry.
  - `zap-templates.ts`: sample zaps, plus `templateSteps()` for the builder prefill (it swaps fields equal to `OWNER_EMAIL` for the signed-in user's email, so a sample never publishes an undeliverable address) and `templateRequestBody()` for the API snippet. `zap-templates.test.ts` keeps samples in step with `action-fields.ts`.

  To add a connector, follow [connectors.md](connectors.md).

- Verify with `bun run typecheck`. With the stack running, create a zap end to end and check the dashboard and detail pages.
